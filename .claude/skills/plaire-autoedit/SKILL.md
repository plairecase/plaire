# Plaire Auto-Edit v2 — инструкция для Claude Code

Строим систему монтажа С НУЛЯ. Прошлая система полностью удалена: не ищи, не восстанавливай и не копируй её код, репозитории, конфиги или workflow. Если найдёшь остатки (`plaire-editor`, `premium.py`, `engines.py`, `ci_run.py`), не трогай их и спроси владельца.

Владелец — соло-предприниматель, бренд **Plaire**, говорит по-русски. Общайся с ним на русском, весь текст на экране и в подписях делай на английском.

**Главный принцип:** сначала маленькая система, которая 7 дней подряд работает без сбоев, потом расширение. Не строй всё сразу (раздел 15).

## 1. Что делает система

Раз в день утром (к 09:00 по Таллину):

1. Синхронизирует с Google Диска **только новые** исходники, 3D-модели, SFX и музыку.
2. Разбирает новые исходники на планы и индексирует их (что в кадре, качество, движение).
3. Монтирует **2 видео** разной длины и разного стиля:
   - **премиум** (Apple-стиль) — по умолчанию длинное, 15–25 с;
   - **нативное** (TikTok-лайфстайл) — по умолчанию короткое, 7–12 с.
   Длина и стиль меняются местами через день, чтобы не путать влияние стиля и влияния длины.
4. К каждому видео делает **обложку** (JPG).
5. По расписанию (по умолчанию пн и чт) делает **пост Instagram** (4:5 и 3:4) и **фото-карусель TikTok**.
6. Рядом с каждым роликом кладёт **подпись + хэштеги** отдельно для TikTok и Instagram.
7. Складывает всё в `Done` и пишет `manifest.json`. Потом его будет читать отдельная вкладка Claude, где владелец по кнопке публикует в TikTok и Instagram. **Эту вкладку и автопостинг сейчас НЕ строим**, только готовим формат вывода (раздел 10).
8. Учитывает, какие ролики сработали (раздел 12), и чаще выбирает то, что продаёт.

**Почему два стиля.** Лучшие ролики @plaire (181K, 164K просмотров) были нативными: ~8 с, жизнь, одна фраза. Владелец хочет премиум. Поэтому система каждый день делает оба стиля, и через 2–3 недели данные покажут, какой стиль лучше. Пропорция задаётся в `config.json` → `style_mix` (по умолчанию `{"premium": 1, "native": 1}`). Если владелец скажет «только премиум», поставь `{"premium": 2, "native": 0}`.

## 2. Инфраструктура

- **Где работает:** GitHub Actions, приватный репозиторий (например `plaire-autoedit`), `ubuntu-latest`.
- **Расписание:** cron `17 6 * * *` (UTC) = 08:17 зимой / 09:17 летом по Таллину. Плюс `workflow_dispatch` с параметрами:
  - `mode`: `daily` | `test` (test = 1 ролик, без записи в `used.json`, папка `Done/TEST_YYYY-MM-DD_HHMM/`);
  - `force`: пересобрать день, даже если он уже есть;
  - `force_posts`: сделать пост и карусель вне расписания;
  - `seed`: число, чтобы воспроизвести конкретный монтаж.
- **Защита от двойного запуска:** `concurrency: { group: plaire-autoedit, cancel-in-progress: false }`. Если в `Done/YYYY-MM-DD/` уже есть `manifest.json`, а `force` не задан, выйти с сообщением «день уже собран». Всё собирается во временной папке и переносится в `Done` одним шагом в конце, так что недособранный день в `Done` не попадает.

### Доступ к Google Диску — токен rclone (решение владельца, 26.11.2026)

Сервисный аккаунт НЕ подходит: у него нет своей квоты, и в обычный «Мой диск» он писать не может (`storageQuotaExceeded`). Google Cloud и платную подписку владелец использовать отказался.

Сделано так (работает с 26.11.2026):
1. Владелец на своём компьютере выполнил `rclone authorize "drive"` (встроенное проверенное приложение rclone, не «Testing», токен не истекает через 7 дней).
2. Строка токена лежит в секрете `GDRIVE_OAUTH_TOKEN`, ID папки Plaire — в `GDRIVE_ROOT_ID`.
3. `scripts/setup_rclone.sh` настраивает remote `gdrive:` через переменные `RCLONE_CONFIG_GDRIVE_*` (чистит следы копирования токена, маскирует его в логе). Код сервисного аккаунта оставлен как запасной (`GDRIVE_SA_JSON`).
4. Если вход слетит (владелец отозвал доступ), запуск падает с понятной ошибкой, владелец повторяет `rclone authorize "drive"` и обновляет секрет.
5. Никогда не выводи содержимое секретов в лог.

### Обязательные секреты

| секрет | зачем |
|---|---|
| `GDRIVE_OAUTH_TOKEN` | доступ к Диску (токен rclone) |
| `GDRIVE_ROOT_ID` | ID папки Plaire |
| `ANTHROPIC_API_KEY` | **обязателен**: разметка кадров, проверка качества, тексты. Без него запуск останавливается с понятной ошибкой, а не работает вслепую |

Модель: `claude-sonnet-5-5`. Ожидаемые расходы — центы в день (512-px кадры, короткие JSON-ответы). Записывай реальный расход по токенам в отчёт.

### Стек

Node 20 + **Remotion** (рендер), `@remotion/three` + `@react-three/fiber` + `three` (3D), Python 3.11 (`opencv-python-headless`, `scenedetect`, `numpy`, `librosa`, `pyloudnorm`), `ffmpeg`/`ffprobe`, rclone. Шрифт TikTok Sans скачивается из официального источника и кешируется.

Лицензия Remotion бесплатна для физлица или компании до 3 человек, владелец подходит. Если это изменится, напомни ему.

### Время запуска: бюджет 40 минут

- Кешируй (`actions/cache` + копия на Диске в `_autoedit_state`) `node_modules`, браузер Remotion, шрифт, `clips_index.json`, 3D-рендеры.
- Скачивай с Диска только новые файлы и только отрезки исходников, которые нужны сегодня (сначала индекс, потом выборка, потом скачивание нужных файлов).
- **Видео рендерится один раз без звука**, затем ffmpeg собирает две версии (`clean` и `music`) с `-c:v copy`. Видео дважды не рендерим.
- **3D рендерится заранее и кешируется:** для каждой модели и сцены — один прозрачный ProRes 4444 / PNG-секвенция в `_autoedit_state/renders3d/<model_hash>/<scene>.mov`. Пересчитывается только при изменении `.glb`. В монтаже 3D — обычный видеослой.
- Меряй время каждого этапа и пиши в отчёт. Если запуск дольше 40 минут — скажи владельцу, какой этап тормозит.
- Бесплатный лимит GitHub для приватных репо — 2000 минут в месяц. Ежедневный запуск плюс тесты должны в него укладываться; веди учёт в отчёте.

### Уведомления о сбое

Если запуск упал или собрал меньше 2 роликов, workflow создаёт issue в репозитории (`gh issue create`) с заголовком «Монтаж YYYY-MM-DD: ошибка» и коротким описанием по-русски: что сломалось и что делать. GitHub отправит владельцу письмо. Если на следующий день всё прошло успешно, issue закрывается.

**Первый шаг при сборке:** выведи дерево `Plaire` на глубину 2, покажи владельцу и подтверди:

## 5. Анализ исходников (индекс клипов)

Индексируются только новые и изменённые файлы (ключ — ID файла на Диске + `modTime` + размер).

Для каждого файла:
1. `ffprobe`: разрешение, fps, длительность, поворот, цветовое пространство.
2. Разбивка на планы (`scenedetect`, ContentDetector), планы короче 0.6 с отбрасываются.
3. Метрики плана: `sharpness`, `exposure`, `motion`, `shake`, `luma_top` (яркость верхних 30 % кадра — для цвета текста).
4. **Разметка зрением (обязательна):** 3 кадра плана (начало/середина/конец, 512 px) → Claude API → строгий JSON (проверяй схему, при ошибке повтор 1 раз):
   ```json
   {"case_visible_ratio": 0.0-1.0, "case_bbox": [x,y,w,h], "color": "cognac|black|both|none",
    "setting": "studio|street|indoor_lifestyle|hands|pocket_bag|packaging|wallet_before|other",
    "action": "static|rotate|open|close|insert|carry|reveal|detail_macro",
    "style_fit": ["premium", "native"], "hero_score": 0-10, "notes": "кратко"}
   ```
   `wallet_before` = кадр «до»: презерватив в кошельке, мятая упаковка, карман без чехла.
5. Сохраняй в `clips_index.json`.

**Правила отбора:**
- план годится, если `case_visible_ratio ≥ 0.8`, он резкий и без пересвета;
- кадр без чехла — только как переход ≤ 0.4 с, или если это `wallet_before` в шаблоне `wallet_vs_case`;
- премиум берёт в основном `studio` и `detail_macro`, нативный — `street`, `hands`, `pocket_bag`, `indoor_lifestyle`.

## 6. Два стиля

### Общие правила для обоих (решения владельца)
- **Никаких фильтров, LUT, цветокоррекции**: свет и цвет исходников как есть. Допустима только техническая нормализация HDR → SDR Rec.709.
- **Никакой чёрной финальной карточки.**
- Один шрифт **TikTok Sans**, внутри ролика один стиль текста.
- Чехол в кадре почти всё время.
- Без эмодзи и стикеров.
- Хук виден с первого кадра (первый кадр = обложка), без логотипа и вступления в начале.
- «condom case» — в тексте на экране или в первой строке подписи.

### Премиум (Apple-стиль)
Ориентиры: Apple «Introducing», AirPods, Dior.
- ≤ 6 слов на экран, один факт на кадр, текст держится ≥ 1.6 с, появляется ~700 мс, ease `cubic-bezier(0.16, 1, 0.3, 1)`.
- Медленный наезд (scale 1.00 → 1.04, решение владельца 26.11.2026), параллакс, speed ramp на 50/60 fps (замедление в момент щелчка магнита), match cut по форме чехла, мягкий push, blur-dissolve. Белая вспышка 2–3 кадра — не чаще раза за ролик.
- Хук: eyebrow (CAPS, 26) + display Light 96 сверху (x 120, y ≈ 300). Выноски — одна на кадр, тонкая линия 300 px к точке 14 px на чехле.
- Цвет текста: `luma_top > 0.6` → ink, иначе белый с мягкой тенью.
- Финал (последние 2–3 с): вордмарк сверху, чехол (видео или 3D), `€29 | • PLAIRE.EU`, строка `Free shipping to all EU countries`. Фон — живой кадр или paper.

### Нативный (TikTok-лайфстайл)
Ориентир — собственные лучшие ролики @plaire: жизнь, руки, клуб, сумка, одна фраза.
- Одна фраза на весь ролик (или две подряд), белый TikTok Sans 600 ~58 px с мягкой тенью, в верхней трети внутри безопасной зоны. Без выносок, без eyebrow, без ценника на экране.
- Быстрые прямые склейки 0.4–1.2 с, в бит; ручная камера допустима. Без зумов, вспышек и графики.
- Финал — последний живой кадр с чехлом, без карточки. CTA только в подписи.
- Цель — выглядеть как ролик человека, а не реклама.

### Тексты: `texts.json`
Банк хуков и CTA на английском, у каждого метка `premium` или `native`, минимум 15 на стиль. Каждый проходит валидатор. Если фраза длиннее 6 слов, она делится на 2 экрана подряд, и на каждом экране ≤ 6 слов.

Примеры (все ≤ 6 слов на экран):
- premium: `Introducing Plaire.` · `Stop keeping condoms in your wallet.` · `Holds 2. Feels like nothing.` · `Eco-leather. Magnetic. Ultra-slim.` · `The condom case, redesigned.`
- native: `Carrying a condom case while clubbing >` · `Finally, a real condom case.` · `POV: no more crushed wrappers` · `It looks like a mini wallet` · `Why I stopped using my wallet`

Новые варианты можно генерировать через Claude API, но каждый проверяется валидатором.

## 7. Шаблоны видео (композиции Remotion)

Каждый шаблон — композиция с параметрами (`clips`, `texts`, `audio_cues`, `use3d`, `seed`).

| id | стиль | длина | идея | что нужно из исходников |
|---|---|---|---|---|
| `p_one_line` | premium | 7–12 с | одна сильная фраза на 2–3 героических планах | 2+ `studio` |
| `p_features` | premium | 15–20 с | 4 выноски: Eco-leather / Holds 2 / Hidden magnetic closure / Ultra-slim | 4+ `studio`/`detail_macro`, 1 `open` |
| `p_introducing` | premium | 15–25 с | «Introducing Plaire»: 3D-раскрытие → студия → жизнь → финал | 3+ `studio`, 1+ `street`, 3D |
| `p_macro` | premium | 7–12 с | почти без текста: фактура, шов, щелчок магнита | 3+ `detail_macro` |
| `n_statement` | native | 7–10 с | одна фраза поверх жизни | 3+ `street`/`hands`/`pocket_bag` |
| `n_greater` | native | 7–9 с | мем «X >» про образ жизни | 3+ lifestyle |
| `n_wallet_vs_case` | native | 8–14 с | «до» (кошелёк, мятая упаковка) → чехол Plaire | **1+ `wallet_before`** + 2 lifestyle |
| `n_day_with` | native | 15–25 с | чехол с тобой весь день: карман, сумка, город, вечер | 5+ lifestyle |
| `n_loop` | native | 7–9 с | бесшовный повтор, последний кадр = первый | 2+ похожих плана |

**Доступность шаблона:** планировщик проверяет колонку «что нужно». Если исходников не хватает, шаблон пропускается в этот день, а в отчёт пишется конкретно: «для `n_wallet_vs_case` снять: презерватив в кошельке / мятая упаковка, 3–5 с». Шаблоны с 3D без `.glb` тоже пропускаются.

Если для стиля нет ни одного доступного шаблона, ролик этого стиля заменяется вторым роликом другого стиля, а в отчёте пишется, что снять.

Длинный ролик (≥ 15 с) должен содержать хотя бы один уличный/лайфстайл план и хотя бы один студийный, если такие планы есть в индексе.

## 8. 3D

- Модели `.glb` из `Plaire/3D` (ожидаются cognac и midnight black). Нормируй по max(x, y, z), Y вверх.
- Сцены: `spin` (стоит, вращается 0→200°), `float` (парит, лёгкая качка), `reveal` (выход из тени, свет скользит по фактуре). Одна мягкая боковая лампа + заполняющая, мягкая контактная тень, прозрачный фон.
- Рендер заранее и в кэш (раздел 2), в монтаже — видеослой.
- Используется **только в премиум-роликах**, примерно в 1 из 3: 3D-хук в начале или 3D-финал с ценником. Плюс статичные 3D-рендеры для обложек, постов IG и каруселей.
- Цвет модели совпадает с цветом чехла в реальных планах ролика.
- Нет `.glb` или рендер упал — собираем без 3D, пишем в отчёт, запуск не падает.

## 9. Звук

**SFX** (`SFX`): классифицируй по имени файла и длине (`whoosh`, `click`, `magnet`, `swoosh`, `tap`, `rise`). Премиум: щелчок магнита на `open/close`, мягкий whoosh на push. Нативный: SFX редко, только если подходит действию. Не больше 1 SFX на 1.5 с.

**Музыка** (`Music`): beat tracking (`librosa`), склейки нативного стиля — в долю, премиум — на сильные доли или фразы. Fade in 0.3 с, fade out 0.8 с. Трек не повторяется чаще раза в 5 дней.

**Громкость:** −14 LUFS интегрально, true peak ≤ −1 dBTP (`pyloudnorm` + `ffmpeg loudnorm` в два прохода). SFX на 6–10 дБ тише музыки.

**Авторские права.** В `Music` лежат **трендовые треки, скачанные из интернета**. Plaire — бизнес-аккаунт: TikTok даёт бизнес-аккаунтам только Commercial Music Library, Instagram может заглушить звук, ограничить показ или удалить ролик. Поэтому:
- видео рендерится один раз, потом собираются **две версии**: `video_clean.mp4` (только SFX) и `video_music.mp4` (музыка + SFX);
- в подписи пиши название трека, BPM и секунду начала, чтобы владелец нашёл этот же звук в библиотеке TikTok/Instagram;
- в `manifest.json` по умолчанию `recommended_version: "clean"`. Объясни это владельцу один раз коротко и не спорь, если он выберет `music`.

## 11. Уникальность

- `used.json`: какие планы (файл + отрезок), шаблоны, хуки, треки использованы и когда.
- Отрезок плана — не чаще раза за 7 дней. Хук — не чаще раза за 14 дней. Шаблон — не два дня подряд.
- Два ролика одного дня отличаются стилем, шаблоном, первым планом и (если есть оба) цветом чехла.
- Исходники за последние 3 дня получают приоритет.
- Если планов мало — повтор разрешён с другим кадрированием, скоростью и текстом, а в отчёт пишется: «нужны новые съёмки: …».

## 12. Обратная связь: что продаёт

`_autoedit_state/performance.json` заполняется вкладкой публикации или вручную (через `workflow_dispatch` с параметром `metrics_csv`, либо владелец правит `metrics` в manifest, а система подбирает их при следующем запуске). Для каждого опубликованного ролика: просмотры, средний процент досмотра, лайки, сохранения, переходы (если есть) — через 48 ч и через 7 дней.

Планировщик:
- считает средний процент досмотра и сохранения по **стилю**, **шаблону** и **хуку**, когда у варианта ≥ 3 публикации;
- выбирает шаблоны и хуки с весами по результату, но **20 % выбора всегда случайные** (чтобы пробовать новое);
- `style_mix` сам не меняет. Раз в неделю (по понедельникам) пишет в отчёт сравнение «премиум vs нативный» и рекомендацию, а решает владелец.
- Пока данных нет, всё выбирается равномерно.

Никогда не выдумывай метрики: если данных нет, так и пиши.

## 13. Проверка качества (до переноса в Done)

**Технически (скрипты):**
- `ffprobe`: правильный размер, длительность в рамках шаблона, есть аудио;
- `blackdetect` и `freezedetect`: нет чёрных кадров, нет зависаний > 0.5 с (кроме намеренного стоп-кадра);
- громкость −14 LUFS ±1, true peak ≤ −1 dBTP;
- весь текст внутри безопасной зоны (bbox слоёв из Remotion);
- доля длительности с чехлом в кадре ≥ 80 % (по `case_visible_ratio` выбранных планов);
- валидатор текста пройден.

**Визуально (Claude API, обязательно):** собери контактный лист — 9 кадров ролика в сетке 3×3 (каждый ~360 px по ширине) + кадр обложки — и отправь в Claude API с чек-листом. Ответ — строгий JSON:
```json
{"pass": true, "issues": [], "checks": {"text_readable": true, "text_not_cut": true,
 "case_visible": true, "no_filters_look": true, "no_black_endcard": true,
 "matches_style": "premium|native", "looks_cheap": false}}
```
Не прошёл — пересобери с другим `seed` (до 3 попыток), потом пропусти ролик и запиши причину в отчёт. Контактный лист — артефакт Actions, в `Done` не кладётся.

## 15. Этапы сборки (не перескакивай)

Показывай результат владельцу после каждого шага и жди «ок».

**Фаза 1 — минимальная система (`"phase": 1`):**
1. Сервисный аккаунт и rclone в Actions, дерево Диска, подтверждение путей.
2. `brand.json`, валидатор текста, `texts.json`.
3. Индекс исходников с разметкой зрением. Отчёт: сколько планов, где чехол, студия/улица, есть ли `wallet_before`.
4. Два шаблона: `p_one_line` и `n_statement`. Только `clean`-звук (SFX), без музыки, без 3D, без постов.
5. Обложки, подписи, `manifest.json`, QC (технический + визуальный), отчёт, issue при сбое, защита от двойного запуска.
6. Включить cron. **Фаза 1 закончена, когда 7 запусков подряд прошли без ручного вмешательства.**

**Фаза 2 — расширение (`"phase": 2`), по одному пункту:**
7. Музыка и версия `music`.
8. Остальные шаблоны (по 1–2 за раз).
9. 3D (кэш рендеров → 3D-финал → 3D-хук).
10. Пост IG и карусель TikTok.
11. Обратная связь (раздел 12).

Правки владельца по стилю — главнее этой инструкции. Когда он что-то меняет, обнови этот файл и `brand.json`.
